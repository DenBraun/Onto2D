# `@onto2d/schemas`

Machine-readable JSON Schema Draft 2020-12 contracts for rule-package inputs,
normalized quantities and typed invariant values, canonical decimals, rounded and unrounded accumulation
results, and evidence, closed package candidate-attribute definitions for
constant, element-invariant, or role-dependent finite scalars and Quantities,
primitives/profiles, materialized elements and primitive depth populations,
typed value and Boolean expressions, predicates,
compiled predicate plans and numeric-policy bindings,
complete graph-predicate evaluations, graph-plus-local-numeric
evaluations, partial graph inputs, and conservative
partial persistent-failure diagnostics, deterministic package monotonicity
falsification audits and separate partial-pruning controller decisions,
audited pre-admission plus raw-frontier recursive pruning generation and
differential censuses at depth one and arbitrary verified target depths,
package-bound local-numeric filter
evaluations and constituent-resolution records, typed finite perturbation
definitions and exact stability witnesses, package-bound functional
score/indeterminate artifacts, complete package-cohort partitions and selector
rankings,
functionals with closed fixed/free/fitted coefficient roles and exact
sensitivity coverage, cohorts/selectors, scientific-Oracle requests, request bindings,
responses, and validation results, the closed source-migration package binding,
frozen source-classification policies, independent annotations, blind
adjudication, immutable post-unblinding amendment logs, frozen and effective
classified-relation/SCC projections, node-resolution policies, reviewed
source-node resolution, and lossless typed condensation,
source migration raw-SCC/classification/resolution reconciliation diagnostics
and complete disposition/level-aware migration metrics, plus verified
source-node/relation/raw-SCC explanation indexes and query results,
plus independently frozen source-cluster concentration reports,
canonical candidates/skeletons, finite decoration inputs, decorated
enumeration/store state, normalized run configuration, content-addressed
package/run candidate bindings, high-level enumeration results, and
reproducibility artifacts, including bounded collapse, level-boundary, and
explicit carrier-promotion sets, plus verified level explanation indexes and
content-addressed candidate explanation snapshots, and integrated verified
level-result censuses, plus semantic run manifests, verified run artifact
bundles/materializations/stores, bound run candidate explanations, and
verified local run-directory receipts, plus separately content-addressed
operational execution records and append receipts.

Quantity and quantity-spec unit fields use the lexical subset of the
`si-multiplicative-v1` grammar. Runtime validation additionally checks the
symbol registry, dimensional exponents, conversion range, and compatibility.
Primitive and materialized-element invariants admit a normalized Quantity or
one exact JSON scalar (`number`, `string`, `boolean`, or `null`); scalar strings
share the 1,024-character expression ceiling. Profile invariant vectors remain
Quantity-valued. Tolerance objects require at least one bound. Quantity semantic, evidence, and
method identifiers use normalized non-empty strings, matching the direct
runtime contract. Candidate and skeleton indices are limited to JavaScript
safe integers, and canonical skeleton edge tuples are unique.
Decorated-enumeration contracts preserve normalized finite node/edge variant
alphabets, the fixed graph policy, separate raw/excluded/canonicalization-
indeterminate/canonical/duplicate counts, and explicit logical-state,
raw-candidate, unique-candidate, or
canonicalization-search exhaustion.
The package profile-composition schema binds the opt-in complete-candidate
gate policy, one canonical transcript per evaluated candidate, exact endpoint
slot consumptions, typed guard evaluations, separate compatible/incompatible/
indeterminate and raw-exclusion counts, terminal status, and dedicated hashes.
Generation schemas embed either that artifact or the explicit disabled
`not-run` state.
Package candidate bindings retain the reproduced package/depth identity,
normalized run hash, the complete materialized primitive population, explicit
depth-selection policy, profile-class provenance, deterministic profile
representative, complete connected-skeleton input, and both semantic and
execution generation limits.
Their node/edge alphabets carry only structural attributes selected by the run
and backed by a compatible package definition. Exact variants copy source
scalar invariants, while profile variants require complete canonical member
consensus; Quantity-valued and formation-dependent sources are not admitted by
this schema version.
Package candidate filter artifacts bind the reproduced package rules and run
binding to a full canonical candidate, target/source population identity,
exact or profile-representative constituent resolution, every supported local
top-level predicate evaluation, its run-bound numeric policy, reconciled
outcome counts, and a local eligibility verdict. The executable numeric subset
is exact dimensionless constant/count arithmetic, exact-decimal or compensated-
binary64 sums over finite scalar or Quantity-valued structural attributes,
compatible derived Quantity addition, dimensionless scalar scaling, and
explicit-semantic general Quantity products,
element-exact, strict profile-wide, and explicit numeric profile-mean invariant resolution for normalized
Quantities plus package-authored scalar symbols, structured candidate-local
invariant failures, scalar and Quantity node/edge balance,
role-filtered directed cycle-edge selection, deterministic single-removal
irreducibility, exhaustive proper-subgraph minimality, exact constituent
novelty, typed exhaustive `stableUnder`, plus direct constant-quantity and scalar
comparison. Quantity sums disclose their
canonical unit/semantic and conservative tolerance-aggregation policy; derived
arithmetic exposes computed provenance and its effective absolute bound.
General local Quantity products require `resultSemantic`; their ordinary
Quantity witnesses retain the multiplied canonical unit, full conservative
interval bound, evidence union, and computed product provenance.
Unrounded values and approximation state are explicit; these artifacts do not
represent selector-based final admission.
The package candidate census schema embeds one complete package enumeration and
every corresponding filter artifact, then records reconciled candidate totals,
Boolean selectivity, the indeterminate ratio and threshold interpretation, and
per-predicate pass/fail/indeterminate, exclusive-rejection, inert, and
dominating diagnostics. It admits only complete generation and remains
strictly pre-selector. Status/reason/nullability branches and zero-population
fields are shape-constrained; executable reproduction verifies hashes,
predicate-ID uniqueness, ordering, arithmetic reconciliation, and all embedded
artifacts.
The package functional evaluation schema binds one exactly reproduced eligible
filter candidate to a normalized functional, analysis, run precision, result
specification, canonical set/invariant/coefficient witnesses, and either a
typed computed score or an explicit indeterminate reason. Its branches require
the diagnostic tolerance target to agree with status; missing-data outcomes
have no fabricated diagnostic or score.
The package cohort-partition schema binds one independently reproducible
complete local-filter census to its normalized rule and preserves all
exclusions, per-candidate key evaluations, deterministic cohort keys and IDs,
and reconciled coverage counts. Its status branches distinguish empty source
populations, source-census indeterminacy, and key indeterminacy; rule-specific
constraints prevent key kinds from drifting from global, singleton,
shared-support, profile-role, or invariant-window semantics. Runtime replay is
still required to prove exact membership, coverage, hashes, and arithmetic.
The package selector-ranking schema binds one verified partition to its
normalized selector, complete per-member functional evaluations, dense ranks,
epsilon extrema, gaps, degeneracy, variational metrics, exclusions, execution
ceiling, and reconciliation counts. Ranked, empty, source-indeterminate, and
member-indeterminate branches prevent unavailable metrics or fabricated
extrema from appearing as complete results. Runtime replay additionally proves
score order, interval components, epsilon comparisons, hashes, and all count
relationships.
The package selector-sensitivity schema binds a verified base ranking to the
normalized sweep policy, exact coefficient factors and witnesses, every
perturbed cohort ranking, complete leader/presentation/top-K comparisons,
execution counts, reasons, points, and verdict. Its branches prohibit false
robustness for empty/no-coefficient inputs and prevent indeterminate variants
from fabricating stability ratios. Runtime replay additionally proves variant
coverage, perturbed arithmetic, denominators, and both report hash domains.
The package selector-admission schema binds a complete local census to every
declared partition/ranking/sensitivity chain, per-candidate selector outcomes,
the intersection of semantic-extremum sets, per-selector censuses, final
reconciliation counts and retention ratios. Its strict local/selector outcome
branches distinguish definite exclusion from missing selection information;
runtime replay additionally proves selector coverage, precedence, all
cross-artifact hashes, counts, ratios, and the admission hash.
The package selected-formations schema binds that admission to one canonical
formation record per definitely selected candidate, retaining the full graph,
constituent resolution, selection witnesses, claims, evidence, and unreduced
admission counts. Its explicit disposition forbids treating the record as a
derived profile or element; runtime replay proves all cross-artifact identity,
lineage, ordering, count, and hash relationships.
The package derived-profiles schema records the frozen residual-slot policy,
directed endpoint-consumption witnesses, typed partner-guard member/check
transcripts, optional formation-functional invariant evaluations, complete
formation-derived type-rule comparisons and assigned tag sets, complete
normalized profiles, and closed indeterminate reasons for unavailable policy,
guards, capacity, or derived values. The dedicated profile-slot-guard schema
closes logical, type-tag, invariant-comparison, and legacy-hash forms. The
derived-depth population schema then constrains all-or-nothing materialization,
derived `Element` records, the external derivation index, identity policy,
counts, interpretation, and population hash.
The package carrier-promotions schema binds the verified source ladder,
bounded collapse/counterexample basis, closed promotion policy, per-source
decisions, evidence-complete immutable mappings, loadable target primitive
inputs, terminal interpretation, and promotion hashes.
The element and primitive-depth schemas separate policy-controlled structural
identity from package/population provenance, require a reproduced canonical
form, fix primitive depth to zero, and forbid formation provenance on primitive
records. Derived population and level schemas retain the optional normalized
run ontology target with independent declared ontology-axis provenance.
Run precision policies select the bounded `decimal-rational-v1` rounding and
summation behavior; schema validation limits `decimalPlaces` to the runtime
maximum but does not execute arithmetic.
The recursive value-expression contract fixes every supported node and
selector shape. Executable analysis additionally resolves declared symbols,
infers dimensions, applies resource limits, and checks result compatibility.
Schema-v1 bounds scalar strings to the analyzer ceiling and canonical node
indices to the JavaScript safe-integer range.
The Boolean-expression schema fixes all built-in and substructure combinator
shapes. Runtime analysis additionally resolves data/perturbation references,
checks comparison and balance dimensions, and derives conservative pruning
facts; the predicate-plan schema records the resulting compiled contract.
The predicate numeric-binding schema records a verified plan identity, one
normalized run precision policy, canonical summation order, versioned
quantity-comparison behavior, and the numeric operations that consume them.
The graph-predicate evaluation schemas bind a verified plan to canonical
candidate identity, effective graph policy, three-valued outcome, and
canonical-index witnesses. Edge-index witness arrays follow the runtime's
explicit safe-integer edge budget rather than the default 64-edge
canonicalization setting. Partial results bind `nodesComplete`, retain static
eligibility/audit state, and require `pruningAuthorized: false`; schema
validity cannot authorize generator pruning.
The local-predicate evaluation schema additionally binds the reproduced
numeric-policy hash, unrounded and rounded decimal results, exactness state,
direct and derived quantity comparisons, canonical node/edge selection
witnesses, source-population-bound exact, complete profile-consensus, or
explicit numeric profile-aggregation
invariant-resolution witnesses, and signed balance aggregates with normalized
threshold comparisons. Cycle selections bind
`directed-cycle-edge-union-v1`; irreducibility witnesses bind the complete run
substructure policy, every skipped/evaluated removal, canonical parent mapping,
and recursive nested witnesses. Minimality witnesses bind exhaustive proper-
subgraph selection and raw/effective parent indexes. Exact novelty witnesses
bind `canonical-single-node-no-edge-v1`, source element and projection
identities, canonical parent mapping, and any nested policy ID without
permitting profile-representative substitution. Profile witnesses bind the complete ordered
member set and either the `identical-normalized-quantity-v1`,
`identical-normalized-scalar-v1`, or
`arithmetic-mean-conservative-v1` policy plus its precision and optional
uncertainty/provenance diagnostic. Unavailable or incomplete
candidate data is represented by an indeterminate comparison witness;
malformed contexts and incompatible runtime types remain invalid.
Typed stability witnesses bind exact or seeded sampled finite single-edit
enumeration, the perturbation-context hash, exact decimal threshold,
reconciled valid/skipped and pass/fail/indeterminate counts, empirical exact
fractions, canonical perturbed-candidate parent mappings, and every skipped
reason. Sampled witnesses additionally bind the SHA-256 rejection stream,
with-replacement frame, requested sample count, frame index per draw, and
conservative joint 95% Chebyshev bounds. The package schema admits both
enumerations for four executable finite definition kinds plus registry-only
strings.
Attribute-sum and balance-selection witnesses additionally require the
attribute value kind, selected accumulation algorithm, and its exactness.
Quantity witnesses also bind unit, semantic, and
`sum-effective-absolute-bounds-v1`. The standalone unrounded-
accumulation schema enforces the same algorithm/exactness relation.
The Oracle binding/result schemas separate normalized semantic request and
response identities from operational wall time and record accepted versus
indeterminate convergence handling.
The source-policy schemas record complete category/disposition vocabularies,
authorship and exposure declarations, a closed classification-visible local
field vocabulary, realizable classifier bounds, risk thresholds, forbidden
inputs and criteria, and lossless edge/cluster invariants. Runtime freezing
additionally checks cross-field exposure coherence, required inputs, and
canonical set ordering; schema validity alone does not authorize a catalogue
decision.
The annotation/adjudication schemas retain the complete classifier-by-relation
matrix, view identity, exposure declarations, raw disagreement, final decisions,
ordered freeze/unblinding times, and disagreement-risk metrics. Runtime
freezing reproduces the upstream policy and annotation hashes and prevents
unanimous results from being silently overwritten.
The classification-view schema binds the exact policy-visible relation payload.
The classified-relations schema preserves every final typed edge and both
directed SCC partitions, including full component membership, internal edge
references, self-loop cyclicity, and upstream policy/view/annotation hashes.

The schemas are a versioned contract surface aligned with the first executable
kernel loader. Passing schema validation is necessary but does not prove
scientific validity or kernel conformance; cross-record references,
stratification, phase acyclicity, structural identity, and other invariants are
executable checks in the kernel and adapters.
