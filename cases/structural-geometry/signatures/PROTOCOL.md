# ResponseSignature-v0: frozen graph-native protocol

Fixed on 2026-09-07 before signature implementation and measured generation.
SG2-024 consumes the existing SG2-021/022 implementations without changing their
policies, preparation, scientific artifacts or source packs.

## Feature map and applicability

Use the existing explicit regime and optional induced/full scope. Execute both
the fixed response registry and four representation invariance probes against
the same verified source. Bind all policies, adapters, implementations, targets,
observations and source/scope identities through the complete embedded evidence.
No caller-supplied outcomes, callbacks, weights or feature subsets are accepted.

Each compatible response probe contributes one mandatory feature in registry
order: feedback, necessary dependency, enabling dependency, direction, support.
Canonical/topology profiles have three features; typed profiles have five.
Each feature is the finite multiset of complete joint component responses over
every eligible target. A row contains the ordered observable ID, exact
equal/different state and scalar integer after-minus-before delta (null for graph
and vector values), plus a positive integer multiplicity. Group equal joint
rows and sort their canonical encodings. Preserve multiplicity; do not normalize
away the number of structural targets or split components into unrelated marginals.
No baseline value, graph hash, source ID, target label, rejection, missingness
code, timing or resource counter is a feature coordinate.

A feature is observed only if selection is complete and nonempty, every target
applies and all mandatory before/after observations are present. Otherwise its
value and value hash are null, retaining coverage, reasons and the full response
evidence separately. Empty selection, unknown necessity, rejected reversals and
missing observations remain distinct. No partial histogram, sentinel or default
zero substitutes for a complete feature. Coverage counts observed features over
the fixed nonempty three/five-feature profile; per-feature pair coverage and
target reasons remain available.

A complete signature additionally requires every invariance control to pass.
Its value is the ordered feature-value tuple. Otherwise its whole value/hash is
null, with incomplete feature or invariance reasons. Complete component values
remain inspectable. Hashes of values bind the fixed profile and feature policy,
not provenance; they are equality fingerprints, not distances or proof of
semantic comparability. Typed signatures retain an explicit source-local
vocabulary comparison context outside their feature values. Any future
cross-source typed comparison must establish semantic authority separately.

The signature layer is response-only and graph-native. History, motif,
closure/admissibility and kernel identity effects have no configured feature
slots or fabricated evidence. SG2-023 remains required before compatible History
profiles ship. R6 must separately freeze distances, weights, scales and domains.
Geometry, higher-order/domain boundary semantics and public scientific claims
retain later gates. Complete equality may merge nonisomorphic graphs.

## Limits and source verification

All upstream graph, target, path, source-audit and byte limits still apply.
The composite allows at most 70 observation evaluations, 140 individually bounded
canonicalizer calls, 64 feature rows and 448 feature component visits. It allows
1,000,000 canonical entries and 8 MiB cumulative/final output with inherited
string/depth limits. Exceeding a bound throws without a partial artifact.
Public verification reconstructs the entire signature from the expected pack
and input, including both evidence artifacts; schema validity and rehashing
alone cannot authorize a value. All outputs are deeply immutable.

## Controls and independent acceptance

Reuse all 16 source-defined response controls. Add canonical/topology versions
of the typed diamond with feedback, and all three regimes for each of:

- Subdivide its feedback edge 3→0 into 3→4→0 with the same necessary annotations.
  This is a structural negative expected to change complete response multisets.
- Add one isolated node. This is an explicitly retained collision candidate:
  a response-only map can ignore an unchanged isolated baseline node.
- Change the contextual edge 0→2 to necessary, preserving its other fields.
  Expect a complete typed feature change and unchanged untyped features.

Freeze these contrasts before evaluating; keep failed expectations and
collisions instead of tuning the map. Source controls, old independent Python
reference dependencies and protocols are SHA-256 bound. Independent Python
reconstructs responses from source selectors, Boolean closure and graph orbits,
then separately aggregates joint rows and strict signature eligibility.
Expectation generation reads no production artifact.
