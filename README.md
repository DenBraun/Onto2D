# Onto2D

Onto2D is an ontology-backed JavaScript toolkit with a deterministic
admissibility-closure kernel for complex-system modelling.

## Current status

The runtime packages form a dependency-free Node.js workspace; repository
schema checks use a lockfile-pinned Ajv development dependency. The
`@onto2d/kernel` package implements the deterministic package and graph-identity foundation,
including normalized package/run binding and finite decorated-candidate
enumeration, verified primitive depth-population materialization, and
graph-only predicate evaluation with conservative partial-failure diagnostics,
package-bound local numeric candidate filtering, and complete local-filter
censuses, plus verified package-bound finite functional scoring for eligible
candidates and verified total partitioning of the complete eligible population
under every schema-v1 cohort rule, plus deterministic complete-cohort
functional ranking with retained epsilon extrema and complete coefficient
sensitivity execution, deterministic all-selector admission, and verified
selected-formation materialization, residual-slot profile extraction, and
verified derived `Element` population materialization, plus verified
formation-functional profile invariant derivation with complete functional
evaluation lineage and all-or-nothing failure semantics, plus
whole-package level transitions over contiguous prior depths and an explicit
bounded closure ladder, including bounded current-level fixpoint rounds when
explicitly enabled. The ladder executes `all-below` or `previous-only`
source semantics, tracks minimum-depth identity and all appearances, and stops
at the requested depth, an element fixpoint, or indeterminacy. Verified profile
collapse and level-boundary diagnostics now feed explicit, evidence-bound
carrier-promotion artifacts and loadable target-package primitive inputs.
Audited recursive edge-decoration pruning is now implemented both at depth one
and at arbitrary target depths bound to a verified contiguous prior-level
chain. It supports undirected, directed-weak, and already-satisfied
directed-strong frontiers, including exact skipped-subtree counts, target/source
population identity, exact replay, and three-layer differential conformance
against pre-admission-only and pruning-disabled execution. Null-model execution
plans now bind complete census carriers, ontology gates, model contracts, and
independent per-trial seed streams. All three carrier-size proposal populations
and occurrence-aware local-predicate trial censuses execute with exact replay.
Trial-local cohorts, functionals, selector extrema, coefficient sensitivity,
and admission now also execute without collapsing replacement duplicates;
per-model distributions, standardized effects, zero-variance notes, and
primitive/generalized-depth plus round-specific current-level baseline
integration now execute with exact replay. Exact incomplete-node frontier
counts and replay-resumable raw traversal execute under ADR-0081. ADR-0082 now
adds separately audited predicate-authorized node-growth pruning at depth one
and arbitrary verified target depths, with exact differential conformance and
a fail-closed `directed-strong` boundary. An identity-bearing opt-in profile-slot
composition gate now excludes complete canonical candidates with insufficient
role/polarity capacity or definitely failed typed partner guards before store
admission at primitive, generalized-depth, and current-level boundaries. It
fails the whole generation on indeterminacy. Audited canonical-prefix pre-
admission pruning now runs after a successful gate with exact depth-one and
generalized-depth differential conformance. Separately audited profile-
extension censuses now also authorize recursive edge-group and node-growth
subtree pruning while preserving exact compatible/excluded counts at both
scopes. Package-authored constant scalar/Quantity
node/edge attributes and element-invariant scalar/Quantity node attributes now enter
primitive, generalized-depth, and current-level candidate alphabets with exact
profile-class consensus. Quantity values are SI-normalized and retain complete
provenance in candidate identity. Closed role maps additionally derive scalar
or Quantity edge values with complete run-role coverage. Formation-functional
Quantities flow acyclically through verified derived `Element` invariants into
later-depth node attributes; same-candidate functional feedback remains
forbidden. Formation-derived type tags now execute from verified
profile-invariant Quantity thresholds with complete comparison lineage.
Explicit numeric profile-invariant arithmetic means, exact
typed single-edit, and seeded sampled
`stableUnder` are executable and auditable.
Verified level explanation indexes now bind every evaluated candidate to its
complete filter, admission, formation, derived-profile, and derived-element
lineage at depth one or any reproduced target depth. Candidate explanation
queries are content-addressed snapshots. The catalogue adapter likewise builds
a verified source-migration index and content-addressed node/relation/raw-SCC
query results once a complete reviewed migration chain is supplied.
The catalogue adapter also derives a content-addressed reconciliation report
from the fully reviewed source chain: raw SCC histograms, all six typed edge
counts, descriptive/nonformation resolution shares, cluster/member counts,
available frozen risk signals, and exact node/edge/DAG conservation. A
separate immutable amendment log now accounts for post-unblinding changes;
non-empty logs are applied through a separately hashed effective projection,
which recomputes SCCs and requires newly bound reviewed resolution and
condensation artifacts. None of this claims a completed current-catalogue
migration.
The adapter can additionally freeze the complete documented migration metric
set once callers provide exactly one reviewed disposition for every raw SCC
and a complete source-catalogue level mapping; cross-level cluster counts and
risk-policy identity are then derived rather than trusted.
An independently frozen bottleneck definition and total source-vertex depth
partition can additionally produce a cluster-concentration result that reports
concentration, uniformity, depletion, or an explicit indeterminate ratio.
Integrated verified level-result censuses now expose reconciled final counts,
Boolean/variational selectivity, predicate and selector censuses, admitted
element IDs, and the original interpretation states for ordinary and
depth-aware closures without presentation-specific data.
Verified run artifact bundles now freeze the complete level chain, semantic
manifest, normalized inputs, level censuses and explanation indexes together
with exact canonical byte references. An explicitly bound verified artifact
store enables `kernel.explain({ runHash, candidateId })` without ambient-state
recomputation; source-migration lookup uses its own verified catalogue-adapter
session rather than ambient kernel state.
The separate `@onto2d/run-store` adapter writes those verified bundles to
portable, atomic run directories and reconstructs every referenced byte before
accepting a persisted result. It also appends independently content-addressed
execution records for timestamps, build/platform labels, resource use, and
terminal status without changing the semantic envelope or `bundleHash`.

## Start developing

Prerequisite: Node.js 20 or newer with npm.

```sh
npm ci
npm test
npm run check
npm run build
```

The runtime packages have no third-party dependencies. Repository schema tests
use the lockfile-pinned Ajv development dependency. `npm run build` performs
repository validation; packages are served directly from checked source, so it
does not create a transpiled `dist/` tree.

Additional commands:

```sh
npm run audit:catalogue
npm run check:docs
npm run check:schemas
npm run test:kernel
```

See [Development Guide](docs/DEVELOPMENT.md) and
[Contributing](CONTRIBUTING.md) for the workflow.

## Repository map

- `scr/` — source catalogue, source schema, and preserved theory PDFs.
- `packages/kernel/` — dependency-free model, canonical graph/hash, and package-loader foundation.
- `packages/schemas/` — versioned machine-readable contracts.
- `packages/catalog-adapter/` — source catalogue loading and read-only audit.
- `packages/scientific-adapter/` — validated boundary for external scientific tools.
- `packages/run-store/` — verified local persistence of run bundles and separate append-only execution records.
- `cases/` — research-case source locks and, later, executable fixtures.
- `scripts/` — zero-dependency repository checks and test orchestration.
- `test/` — cross-package, source-lock, and golden fixtures.
- `docs/` — normative architecture, development plan, and design decisions.

The exact current layout and intended growth path are documented in
[Project Structure](docs/PROJECT_STRUCTURE.md).
